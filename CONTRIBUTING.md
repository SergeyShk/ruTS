# Участие в проекте

Баг-репорты, идеи и пул-реквесты приветствуются. Английская версия README - [README.en.md](README.en.md); общаться в issues и пул-реквестах можно по-русски и по-английски.

## Сообщить об ошибке или предложить идею

Откройте [issue](https://github.com/SergeyShk/ruTS/issues/new/choose) по шаблону. Для ошибки нужны минимальный пример кода с текстом, на котором она воспроизводится, ожидаемое и фактическое поведение, версии ruTS, Python и ОС. Для идеи - какую статистику или инструмент вы хотите получить и на какой источник (статью, библиотеку) он опирается: библиотека следует опубликованным определениям, а не собственным формулам.

## Окружение разработки

Проект использует [uv](https://docs.astral.sh/uv/) для управления зависимостями и [ruff](https://docs.astral.sh/ruff/) для линтинга и форматирования. Требуется Python 3.11 или новее.

```bash
git clone https://github.com/SergeyShk/ruTS.git
cd ruTS

make deps        # создать окружение и установить все зависимости
make nltk-data   # загрузить данные NLTK, нужные для тестов
uv run pre-commit install   # хуки: линтеры на коммите, тесты на пуше
```

Полный список команд - `make help`.

## Проверки

Перед отправкой пул-реквеста должны проходить:

```bash
make lint        # ruff check, ruff format --check, mypy
make test        # pytest: тесты и примеры из докстрингов (doctest)
make docs-build  # mkdocs build --strict, если менялась документация
```

То же самое выполняет CI на Python 3.11-3.14 (Linux), а также на Windows и macOS для одной версии Python. Тесты с маркером `network` ходят в сеть (загрузка наборов данных); локально их можно отключить: `uv run pytest -m "not network"`. Примеры из докстрингов наборов данных выполняются, только если набор загружен в `ruts_data/`; без данных они пропускаются.

## Что ожидается в пул-реквесте

- **Одна тема - один пул-реквест.** Правки не по теме лучше вынести отдельно.
- **Тесты.** Новый код покрыт тестами в `tests/` (структура повторяет пакет), покрытие не ниже 90 %. Значения новых метрик проверяются на примере, посчитанном вручную или сверенном с эталонной реализацией (koRpus, quanteda, stylo, NLTK и т. п.).
- **Документация.** У каждого модуля есть страница в `docs/`; документация двуязычная - русская страница `docs/*.md` и английская `docs/*.en.md` рядом, тест `tests/test_docs.py` следит, чтобы у них совпадали разделы, якоря и ссылки. Изменения в README вносятся в обе версии: `README.md` и `README.en.md`. Примеры в докстрингах и документации показывают фактический вывод.
- **Источники.** Для новой статистики в докстринге и на странице документации указывается источник формулы; реализация сверяется с ним, расхождения с другими библиотеками оговариваются явно.
- **Совместимость.** Изменение поведения существующих статистик и сигнатур - только с пояснением в описании пул-реквеста: оно попадёт в заметки релиза.
- **Стиль.** Код форматируется ruff (`make format`), типы проверяются mypy, докстринги на русском в принятом в проекте формате (`Описание`, `Аргументы`, `Вывод`, `Исключения`). Комментарии в коде не дублируют то, что видно из него самого.
- **Коммиты.** Сообщения на русском в повелительном наклонении: «Добавить …», «Исправить …», «Убрать …».

Описание пул-реквеста отвечает на два вопроса: что сделано и почему. Если пул-реквест закрывает issue, укажите его номер.

## Как устроен репозиторий

- `ruts/` - пакет: классы статистик, экстракторы, `corpus/`, `datasets/`, `visualizers/`, `resources/`.
- `tests/` - тесты, повторяющие структуру пакета; `conftest.py` в корне обслуживает doctest.
- `docs/` - документация MkDocs (Material), `mkdocs.yml` - навигация и перевод её на английский.
- `demo/` - демо на Gradio для Hugging Face Spaces.
- `examples/` - ноутбуки с примерами; после правок выполняются командой `make notebooks`, выводы хранятся в файлах.
- `.github/workflows/` - CI (`ci.yml`), публикация (`publish.yml`), документация (`docs.yml`), демо (`demo.yml`), ноутбуки (`examples.yml`, по расписанию и вручную).

Версия хранится только в `pyproject.toml`; релизы выпускаются через GitHub Release, изменения описываются в его заметках, отдельного файла CHANGELOG нет.
